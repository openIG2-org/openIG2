## Reading big outputs
- `ghidra/slice_decomp.py FILE --list | --story ID [--pair EXE.c] | --block N | --lines A-B | --grep RX`: one story block (or range) of a big decompile or disassembly; the ELF's `st_Story(id, 1)` blocks pair with the exe's by ordinal. `slice_decomp.py DIR --list` lists a decompile folder by size.
- `trace/summarize.py FILE_OR_DIR... [--glob G] [--show KIND -n N]`: per trace file the record counts per kind, the seq/ido range, alerts (fault, stall, hang, death, win, ...) and the last records, one line each.

## Ghidra, Frida and tracer notes
- Decompile ELF functions: `cmd //c "<ghidra>\\support\\analyzeHeadless.bat <repo>\\_local\\ghidra ig2 -process ig2 -noanalysis -readOnly -scriptPath <repo>\\tools\\ghidra -postScript DecompileFunctions.java <outdir> <names or 0xaddr…>"` (`-process ig2.exe` for the exe). `LoadScenario` is too big to decompile (timeout).
- ELF quick facts: file offset = VA − 0x400000 for .text/.rodata; .data VA 0x114bc60 ↔ file 0xb4bc60. `nm -S -C --defined-only ig2` gives data tables with sizes.
- Frida: `_local/venv/Scripts/python.exe tools/trace/run_trace.py <install> <out.jsonl>`. It spawns ig2.exe (windowed) and starts `scenario/quick.scn` by calling `Betolt_Scenario` (exe 0x4f5ba0) from the per-frame hook `Fake_FRISSITES` (exe 0x4de720); `IG2_gameUpdate` is entered only once. The exe is ASLR-relocated: rebase from image base 0x400000. Colony economy: `tools/trace/run_colony.py <install> _local/traces/colony.jsonl [--fuzz]` (before/after snapshots of every `FRISSIT_Planet(true,0)`; `--fuzz` randomises live planet state first, which found two spec errors). Fleet movement + radar: `tools/trace/run_fleet.py <install> _local/traces/fleet.jsonl [--fuzz] [--fuzz-radar] [--mp-move]` (`--mp-move` stages a second human EN in MP mode, wormholes via AddWormhole and attacks; per-tick snapshots of `FRISSIT_Starmap`; dump freed slots too, the game reads stale records; `--fuzz-radar` perturbs alliances, owners, radar stations, stealth, story fields; `--fuzz-approach` stages unseen enemy attacks on the human at ×16 → `fleet-approach.jsonl`, pinning the same-tick "enemy approaching" slow-down).
- Colony side systems: `tools/trace/run_colony_side.py <install> <out> --mode economy|elfoglal|fellazad|colonise|money|arrive [--fuzz] [--seed S]`. Record to `pending-*.jsonl` and rename to `side-*.jsonl` when done (the replay globs `side-*`). Agent lessons: call `rndlog` with a source path containing a backslash (else NULL deref); x87 `st0` returns (`float10`, e.g. `MoneyMennyi`) need an `X86Writer` thunk with `fstp`; apply direct-call set-up before the "before" snapshot; conquering free building-less planets crashes the game (use owned planets). Rust side: `serde_json` needs `float_roundtrip` for exact f64.
- Game end: `tools/trace/run_gameend.py <install> <out> --mode win|lose|quiet [--plant]` (`gameend.js`): quick.scn, the starmap (`AktKepKell` 2; the load alone stays on screen 15), then a staged end (win: every other `BirodalomEl` 0; lose: the human planetless and AI-run, the day's death check kills it; quiet: `MEGNYERES(0)`); `st_ShowAnim` logged, not played; the exit flags, screen changes and every `LoadHighscores` table logged. `--plant` writes test high-score tables into `options.dat` and restores the file afterwards (re/rules/game-end.md).
- Space combat: `tools/trace/run_spacewar.py <install> <out> --mode design|auto|indit [--fuzz] [--count N] [--seed S]`. The agent calls the exe functions directly from the frame hook; quick.scn has no warships, so it first builds fleets with the exe's `FlottaNew`/`HajoNew`/`TankNew` (0x53d400/0x53e800/0x541750). **Frida 17: the agent's own Interceptor hooks don't fire inside its `NativeFunction` calls** (even with `traps: 'all'`): compare state instead. Fuzzed auto-resolves crash the exe after ~50–60 battles (accumulated fuzz state): record several short sessions with different seeds.
- REA MCP on this host: the Windows Ghidra provider is read-only and times out on the exe; REA's Frida provider lacks bindings. Use headless Ghidra plus Python Frida instead.
- Frida `Interceptor.attach` probes don't fire for calls made from the agent's own thread (e.g. an order the tracer sends itself): use a call stub at the call site (`ground_rt.js`, 0x46f49d).
- Shell heredocs mangle backslashes and quotes: put Python helpers in files (scratchpad) and run them with `python -I`.
- Frame-exact sequences (`run_screen.py --script`, re/screens/sound.md §3): PrintWindow grabs lag the frame they were asked for (the game draws on while the driver grabs); read the frame back inside the game at `SwapBuffers` instead, and replace `SDL_GetTicks` (exe 0x689e80) with a clock that moves 10 ms a `Fake_FRISSITES`, so each drawn frame runs one UI tick (the swaps came on one thread, ticks == t on every grab). `sound.js` also hooks `WF::PlaySpeechGrWar` (exe 0x48c670) and `SpeakingDirector::Play` (0x563cd0); `scripts/grwar-voices.json` is the ground war's voice script. It also logs the music (`PlayMusicExistCheck` exe 0x540430), track loads and the fade/duck levels (`FRISSIT2_SoundSystem` exe 0x55c4f0); `run_screen.py` writes them (`re/screens/audio.md` §8). Inject input by calling `MainCallBackEventHandler` (exe 0x4e2db0) with an SDL2 event; the hooks of the same agent don't see it, so the injector logs it. At start-up the exe gets real SDL key events (Alt, Ctrl, Tab) with only `sym` valid: a sound outside a script is put down to a stale input.
- Scripts also record the script's `Multi_Send` calls as `{k:'msg', t, type, from, fields}` (printed `msg 0x..`, written to the sounds log). SDL key events carry no text character, so char-keyed handlers (`r` on the design screen, name typing) can't be driven; `SDL_KEYS` has every lower-case letter and backspace.
