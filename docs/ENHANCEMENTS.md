# Enhancements

The plan list of *enhanced* options: deliberate, opt-in improvements over the original. The classic ruleset and
client stay as the GOG release; every enhancement can be switched off (`CONTRIBUTING.md`). Port differences that
should match the original are not here: they live in `re/deviations.md`.

How an idea moves:
1. **Ideas**: anyone adds a row (what it changes, why a player would want it, the spec it touches).
2. **Proposed**: the row is specific enough to decide (the exact behaviour, the classic setting, the cost).
3. The maintainers accept or reject it. Accepted: an ADR in `docs/decisions/`, a task line in `TASKS.md`, the
   implementation. Rejected: the row is deleted (git history keeps it).
4. **Shipped**: the option exists; the row names its setting and ADR.

Ideas have no number; a row gets one when it is proposed. Numbers are shared with `re/deviations.md` (one
counter): a proposed row takes the next free number there (484).

## Ideas

Grouped by area; sizes are rough guesses for one developer.

| Area | Idea | Why | Rough size |
|---|---|---|---|
| Mods | Everything moddable: today mods replace files, patch the existing rule tables' values (ADR 0044), add texture/model packs, themes and stories (ADR 0061), but can't add new entries. Next, in phases: (1) new entries in every table: techs, ship hulls and parts, weapons, buildings, tanks and ground units, planet types, races (with pictures, texts, diplomacy lines, AI priorities), each with its own ids beside the original's; the sim and the screens take tables of any length; (2) new scenarios and galaxy maps as data; (3) a sandboxed script layer (e.g. Rhai, pure Rust, deterministic) for rules and events: hooks on the sim's tick, orders, battles and the AI, lockstep-safe and in the save; (4) new UI panels and screens through the egui layer from a script or data. `ig2-check` validates all of it; multiplayer requires the same mods (fingerprint) | players can add or change anything, not just tweak values; the game lives on through its community | months, phase by phase |
| Mods | Easy mods: a mod is one `.zip` (or a folder) dropped into a `mods` folder beside the game's executable (the settings folder's `mods` still read); the game reads zips directly, no unpacking; a `mod.toml` inside gives its name, author, version, description and picture. | Speed | Optimisation: profile the frame and the sim tick (`docs/perf.md`), faster loading, fewer draw calls | smooth play at high refresh rates and on weak machines | part 1 done (`docs/perf.md` → Measurements: start 2.2 → 0.7 s, the ground war's rebuild hitch 24 → 4 ms, a late tick −16 %); part 2 done (`docs/perf.md` → part 2: start with texture upscaling 5.6–7.1 → 2.5–3.9 s, the starmap's ground-war marks 0.15 → 0.09 ms a tick; frames 1–2.5 ms with every option on); next: the battle status's walk over every planet, state views kept decoded across a tick's systems, the hires textures' levels off the frame thread, the colony rebuild's meshes, the device made while the rules load |
| Story mods | Part 1 is done (ADR 0061: the `stories.toml` format, the core triggers and actions, save/load, the lockstep hash, `ig2-check`); next: more triggers and actions (battles, techs, money, relations, spy reports, timers, repeating stories, diplomacy, buildings) and a worked example mod in `docs/USER_GUIDE.md` | new campaigns and race stories from players | weeks |
| Content | **Decided: as mods only, through the rule-table patches (ADR 0044); the project makes none.** More races (rules, diplomacy lines, pictures) | more variety | months, plus art |
| Platform | Play in the browser: open a URL, the main menu loads; the player picks their own install folder, the browser keeps the files (OPFS), the game data is never hosted. Work: a wasm32 build (wgpu WebGPU/WebGL2, winit, an async main loop), a virtual file layer for the install and the saves, WebAudio via cpal, videos through WebCodecs instead of openh264, the web clipboard instead of arboard; multiplayer over WebRTC or WebTransport through the rendezvous/relay service (ADR 0018). Part 1 done: `ig2-formats`, `ig2-rules` and `ig2-sim` build for wasm32 (install files behind `vfs::Files`, a CI check; ADR 0047 has the full plan).
