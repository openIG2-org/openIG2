# Passability maps (`PlanetAtjarasMap::GenerateMap`): runtime verification (2026-10-16)

Spec: `re/rules/ground-combat.md` §11.13. Port: `engine/crates/ig2-sim/src/ground/atjaras.rs`
(`ground::generate_map`), slope limits `ig2-rules::ground_slope_limits` (exe 0x8F8574). Replays:
`tests/atjaras_trace.rs` (direct calls) and `tests/ground_rt_trace.rs` (builds inside the recorded battles).
Tracer: `tools/trace/run_atjmap.py` + `atjmap.js` (Frida 17, GOG `ig2.exe`, `scenario/quick.scn`).

## Method
From the per-frame hook, after quick.scn is loaded, each probe picks a planet `p` and a colony map `m`, sets
the planet's map byte `+0x23` to `m` for the call and calls `GenerateMap(p − 1, 0)` (thiscall) on a zeroed
scratch 0x24-byte object, so the planets' own maps stay untouched. A third of the probes first write a random
leftover start into the globals 0x99644C/0x996450 (layer 1 always searches its own). Recorded: the live
record `Terepek[m]` (0x2714 bytes: masks, heights `+0x138c`, base `+0x84`), the 102 bytes after its height
grid (the head of record `m + 1`), the start globals before and after, the object's nine dwords and the four
maps (run-length coded). The first 75 probes of every run cover all colony maps as loaded; with `--fuzz` the
rest perturb the record for the call (restored after): noise (amplitude 4..120), cliffs and pits, a rough
field with smooth pockets (several layer-1 refills), a flat plateau, a tilt, obstacle blobs in mask B (or a
cleared mask B), random words in the next record's head.

## Result
- **1,085 of 1,085 calls exact** (all 75 colony maps six times over, 635 fuzzed records): every cell of the
  four layers (173.6 M cells), the pointer copy `[6] = [2]`, the start left in the globals.
- Layer 1 refilled in 290 calls (up to 45 fills: the 7000-cell rule and the ring search).
- 621 calls (237 of the 450 unfuzzed ones) come out differently when the heights past the grid read as 0: the
  exe reads height row 50 from the next record's head (a heap pointer and leftover string bytes, different in
  every run). For the unfuzzed maps the difference never leaves the strip `y ≥ 195`.
- **Inside the battles** (`ground_rt_trace.rs`): all 14 builds of a planet's maps during the 17,497 recorded
  `WF::Refresh` ticks are now generated by the port from the live record in the battle's metadata and
  compared with the exe's. 9 are exact as they stand; in 5 the strip `y ≥ 195` differs, because the next
  record's head was never recorded there. The replay takes that strip from the exe's maps, and every cell
  outside it matches. The battle replay stays 17,497 / 17,497 exact.

## Findings
- **Original overrun/hang:** without a layer-1 region of 7000 cells, the ring search fails and the fill
  restarts at (100, 100). If that cell is blocked, the fill floods the blocked cells, the border and the
  heap past the map; that is how five fuzzed recordings crashed the game (the tracer's fuzz now keeps one
  big smooth pocket and only contiguous plateaus). If the cell is a dropped small region, the loop never
  ends. The port stops after that fill and reports `hung`. No shipped map gets there.
- **Original nondeterminism:** the far strip's heights come from the next record's head (above).
- The decompile's backward-sweep slope pointer (`+0x4e1fb`) is right (8·39999 + 3); the asm is all scalar
  SSE: the slope product and the clamp tests are f64, the class product f32.
- The two-gentle-directions rule: only when they lie on different axes.
- The planet object as `GenerateMap` sees it starts 4 bytes before the path search's view
  (`ESI = 0xA33384 + p·0x24`): the scratch slope buffer sits in the previous planet's spare slot.

## Mutation pass
31 single-point mutations of `atjaras.rs` against the direct-call replay; **23 caught** (8 to 3,936 call
mismatches). The 8 that survive can't change any result with the shipped limits (layer 1 the strictest, layer 3 above every class): the slope
sign (only |class| is read), clamping to ±2.8 (classes 28 and 29 lie above every limit but layer 3's, which
passes everything), layer 3's unconditional open (every class ≤ 29 passes its limit), refills in layers 2..4 (a start in layer
1's region is gentle in every looser layer), the row wrap of `n − 1` (only the border, which is never
reached), using the neighbour's class instead of the cell's (the class is symmetric), and an f32 slope
product (it differs from the asm's f64 at exactly 3 boundaries in ±2.9, classes 10/11, 16/17 and 21/22, none
at a limit: pinned by a unit test).

## Not covered
Editor mode (`GenerateMap(p, 1)`, layer 0 and mask A written back: not ported), the hang/overrun itself
(the exe crashes), maps changed at run time other than by the fuzz.
